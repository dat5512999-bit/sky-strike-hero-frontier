# 劇情逐幕配樂 v1.0.0（併入 v0.85.85）

## 產品需求與取捨

使用者希望每段劇情有符合情緒的音樂，例如開心、振奮與緊張。現況僅有戰場短音效，劇情卡沒有配樂。此次涵蓋四章 16 關及西境預告共 86 幕，不改劇本文字或戰鬥。每幕不是一首獨立歌曲，而是從九種原創短主題中指定最合適的情緒；相鄰幕次依敘事轉換，避免同關五幕一直播放同一段。未採外部歌曲，以免授權、網路依賴與大檔下載問題。程序合成是可用的第一版，若日後要升級成錄音室級管弦配樂，可保留 `musicMood` 資料契約並替換聲音來源。

## 敘事與介面

九種主題：探索、謎團、不安、低迴、緊張、決心、振奮、希望、欣喜。各關逐幕指定 `musicMood`；例如「夜守校準」是「不安 → 低迴 → 緊張 → 振奮 → 希望」，「西境信號」在談判後以欣喜收束。這是情緒詮釋，不增加或改寫世界觀結論。

劇情卡底部顯示「本幕：情緒」和「♫ 音樂：開／關」。開關只控制劇情配樂，與戰場「英雄攻擊音效」分開，選擇存在此裝置的瀏覽器儲存空間；不改玩家檔案。手機橫向維持可觸控的按鈕，緊湊畫面省略情緒文字但保留開關。若瀏覽器不支援 Web Audio，按鈕顯示不可用。瀏覽器禁止自動播放時，點一下音樂開關即可在使用者手勢中啟用；關閉音樂或離開劇情不阻擋閱讀。

## 架構、資料流與效能

`src/td/app/StoryCatalog.js` 的 `storyBeatScores[mission.id]` 逐幕指定情緒並檢查長度；`storyCards[].musicMood` 交給 `src/td/app/FrontierApp.js`。後者依劇情頁生命週期呼叫 `src/td/app/StoryMusic.js`：切幕轉換主題、回顧結束／跳過／進入戰鬥／回大廳／開商城／切出頁面時停止。`td.html` 在 `FrontierApp.js` 前載入模組；`sw.js` 把程式加入離線殼。

配樂使用瀏覽器 Web Audio 的原創和弦、低音與旋律，不需 HTTP API、資料庫、外部音檔或新執行套件。單一排程計時器只在劇情播放時運行，提前 220 ms 排音符、同時最多 24 聲部，切幕約 0.38–0.55 秒淡出／淡入。離開頁面清除排程，背景分頁暫停；不在戰鬥循環執行。配樂開關 key 為 `heroFrontierStoryMusic`，與戰鬥音效 key `heroFrontierFrostAudio` 不同。

## 測試、部署與回復

`node --test tests/td-story-music.test.js` 驗證 86 幕情緒標註、主題存在、音樂開關持久化、切幕不重複建立排程、離開劇情即停；`node --check src/td/app/StoryMusic.js`、`npm run check`、`npm test` 為完整回歸。Edge 本機頁面核對「夜守校準」從不安切到低迴、開關狀態、離開回顧後停止，無腳本錯誤；844×390 橫向畫面無水平溢出且開關在可視範圍。真機音質、音量與瀏覽器自動播放策略仍應在發布前複驗。

v0.85.85 整合結果：`npm test` 1003/1003、`npm run check`、`npm run check:release` 及 `git diff --check` 均通過，並新增音訊裝置失敗不佔用聲道測試。先前 Edge 音訊分析器確認輸出非零波形；這不代替真人聆聽與不同手機喇叭測試。

此功能版本 **v1.0.0** 併入應用 **v0.85.85**；`StoryCatalog.js`、`StoryMusic.js`、`FrontierApp.js`、`td.html`、`td-lobby.css`、`sw.js`、測試及文件須成套發布。Pages 檔案一致性可驗證，但「實際有聲」仍需玩家裝置聆聽，不能由 HTTP 回應證明。回復時保存前一完整 Git 提交與玩家 JSON，成套回退程式和快取鍵，無需遷移存檔。建議後續以玩家聆聽回饋決定是否把九個主題升級為錄製配樂。
