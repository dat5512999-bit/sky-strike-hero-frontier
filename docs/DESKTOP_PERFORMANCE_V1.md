# 電腦版卡頓修正 PERF 1.0.0（本機、未部署）

## 需求與證據

玩家使用電腦；提供的畫面是第 9／50 波、×2、剩餘 16 敵人，不能只歸因於後期大量敵人。截圖可見重疊傷害／金幣文字，但截圖本身無法提供 FPS。

程式檢查發現：每個畫面更新都呼叫完整 updateUi（包括未開啟商店內容與兵種卡片），直接地圖每幀套色彩濾鏡，相同浮動文字每幀重新描邊及填字。這次只減少重複工作，不降低地圖解析度、不改戰鬥速度或數值。

## 調整內容與架構

1. TDGame.loop 的被動介面刷新上限改為 10 Hz；戰鬥更新、畫面繪製與 ×2 遊戲速度不變。點擊、購買、選取等事件仍立即 updateUi，冷卻／數字最長約 100 ms 更新。
2. FrontierTerrain.filteredImage 將地圖濾鏡在原始解析度預先繪製一次。來源物件或尺寸改變即重建，一次只保留一張，超過 8,388,608 像素或不支援 Canvas 時退回原路徑。
3. 新 CombatTextCache 重用浮動傷害、金幣和治療文字。保留顏色、描邊、數值、透明淡出與移動；依畫布變換以足夠解析度建立文字，超過 3 倍縮放退回原繪製。最多 128 條／524,288 像素（約 2 MiB RGBA），LRU 淘汰；戰鬥 reset 清除。
4. RAF 回呼重用綁定函式，避免每幀分配新 bound function。

```text
RAF → 戰鬥更新（原速度）→ 被動 updateUi（最多 10 Hz）→ 原畫面繪製
玩家操作 → updateUi（立即）
地圖圖檔 → 一次濾鏡快取 → 每幀貼圖
傷害事件 → 原始數值 → 有界文字快取 → 每幀透明／位置合成
```

不新增 HTTP API、資料庫、網路服務、權限或持久存檔欄位。新增程式 API：CombatTextCache.surface、draw、clear；模組版本 1.0.0。入口和 sw.js 已列入模組，主發行版本沿用工作區流程，尚未部署。

## 驗證

- `node --test tests/td-desktop-performance.test.js`：4／4，涵蓋介面刷新上限、戰鬥／畫面頻率、操作立即更新、地圖快取失效、文字重用／高 DPI／記憶體上限、無 Canvas 降級。
- 與 frame pacing、娜迦技能回歸合跑：32／32 通過。
- 全量檢查當時 806 項、803 通過，3 項既有地圖路線／障礙測試失敗；本次沒有修地圖。
- 語法、diff 空白檢查通過。
- 原生 Canvas 局部對照：相同地圖＋60 個浮動文字、100 幀、前 10 幀暖機；每幀讀回一個像素強制完成繪製，不只量提交指令。
- 最新測量中位數 5.82 → 2.69 ms；P95 6.29 → 5.73 ms。P95 受環境波動影響，不以最好一次測量當保證。
- 文字 -132 在整數座標的原生像素對照，差異大於 2 的色彩通道數為 0。
- 這不是完整遊戲／瀏覽器 FPS，沒有宣稱玩家電腦或真手機已驗收。之前原生混戰腳本也不包含完整 DOM 成本。

完整結果：`artifacts/desktop-performance-v1/results.json`。基準脚本：`scripts/benchmark-desktop-render.cjs`，需已具備 `@napi-rs/canvas` 的 Node 環境；遊戲本身無此依賴。

## 使用、安裝與部署

沿用主安裝手冊，無新玩家設定。已開啟的遊戲不會熱替換 JavaScript：先保留進度，再重新載入更新過的本機遊戲。若使用線上網址，必須先將這些變更部署到該網址，僅修改本機不會生效。

發行應整包包含 CombatTextCache、FrontierTerrain、CombatFeedbackSystem、TDGame、td.html 與 sw.js，並同步正式版號及快取，保留既有素材。不要透過清除網站儲存空間處理更新，避免誤刪玩家進度。

## 管理、FAQ、備份回復

- 仍有卡頓？開啟遊戲既有「顯示效能資訊」，保留 FPS、影格 P95、更新 P95、繪圖呼叫 P95、速度及怪物數截圖。UI 面板只顯示繪圖呼叫耗時，不能等同 GPU 完成時間。
- 畫面或文字是否降畫質？沒有縮小地圖；文字快取依變換解析度建立，大倍率時退回原方式。
- 傷害／金幣是否被合併或刪除？沒有；本次不改數值與顯示內容，僅重用已繪好的文字，因此重疊文字布局仍是可另行改善的項目。
- 回復：保留上一版完整發行包與玩家匯出備份；以新回退版號整包復原，不需存檔遷移，不覆蓋其他任務未提交修改。
