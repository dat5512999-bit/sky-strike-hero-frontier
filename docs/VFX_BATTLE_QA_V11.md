# 戰鬥特效驗收與修正：Unit VFX 1.1.0（未部署）

## 本次範圍與結論

依使用者確認，優先檢查出手、命中同步，以及塔、士兵與英雄同時攻擊的混戰負載。沒有擴充怪物／召喚物技能、沒有新增素材或改戰鬥數值。

已完成正式戰鬥邏輯測試、原生 Canvas 混戰測試與畫面檢視；**尚未完成瀏覽器實戰與實體手機驗收**，不能把原生 Canvas 耗時換算為手機 FPS。先前瀏覽器讀取遊戲頁面的權限限制未以其他工具繞過；本次使用本機程式與專案素材，不讀玩家存檔。

## 重現並修復的問題

1. 霜原兵：在 30／60 FPS，發射時可能仍是蓄力幀。角色顯示改依 released 狀態進入出手幀，不移動真正發射時間。
2. 衝鋒兵：原固定 0.85 秒往返動畫與高速傷害投射不同步；日耀騎士在目標 x=190 扣血时，身體僅到 x≈130.7。現在只讓畫面追蹤投射進度，命中即到目標，0.18 秒返回；取消也能返回。不改部署錨點、射程、攻速與傷害。
3. 命中特效被尾跡擠掉：每幀總預算不增加，保留一半供命中使用。裝飾最多先用一半，命中可取剩餘額度；塔的連鎖逐點扣除。0 預算仍不畫裝飾。
4. 怪物受擊位移漏還原 Canvas：正常存活分支少一次 restore，後續單位的變換逐幀累積。只補畫布還原，不擴充敵方特效。壓測加入逐單位變換矩陣檢查，失敗即停止。

手機模式同時存在超過 48 個投射／命中物件時，塔與士兵暫時省略尾跡與餘波，保留彈道和命中核心。下降到門檻以下自動恢復，不更改使用者的「減少特效」設定或存檔。

## 架構、API 與維護

```text
Projectile.update → advance（原戰鬥流程）→ UnitVFX.trackCharge（只跟隨畫面）
FrostlandAnimation.pose → released 決定出手幀
Projectile.beginFrame → claimEffect（裝飾）／claimImpact（命中）
Monster.draw → 成對 save／restore → 下一個單位
```

新增 `Projectile.claimImpact()`；`beginFrame(limit)` 設總額及命中保留額。`UnitVFX.trackCharge(p)` 更新原 excursion 的暫時視覺欄位，不增加物件循環引用或持久資料。無新資料庫、HTTP API、帳號權限或外部執行期依賴。

## 安裝、操作、部署、備份與回復

安裝沿用主專案手冊，Node 18+。一般遊戲不需安裝新套件。開發者重跑原生壓測須有 `@napi-rs/canvas`，執行 `npm run qa:vfx-battle`；本次使用既有 Codex Node 依賴。

一般玩家無額外設定。手機高負載保護自動生效；「減少特效」仍可手動選擇。預覽 `unit-vfx-preview.html` 使用展示時序，不替代真實戰鬥同步驗收。

主專案版本仍由工作區發行流程管理；UnitVFX 模組為 1.1.0，未部署、未提交 Git。發行須整包包含 UnitVFX、Projectile、CombatUnit、FrostlandAnimation、Monster、PaintedTowerVFX、TowerVFX、入口和既有圖集及快取清單。依發行流程更新主版號／快取，不能只更新單一特效檔。

發行前保存上一版完整包、玩家匯出備份及本次變更清單；回退應以新的回退版號還原整包，不需存檔遷移，不覆蓋其他未提交工作。
