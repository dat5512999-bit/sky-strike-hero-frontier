# 戰場美術與效能驗收規格 v1.1.0

更新：2026-10-06。此文件是新增／修改英雄、士兵、塔、地圖、技能時的共同交付門檻；規格版號獨立於正式遊戲版號。從 Warcraft III 的研究只吸收可讀輪廓、攻擊預告與命中回饋、地形層次及大量單位時的清楚層級；不得複製其 MPQ 素材、角色、圖示、音效或地圖。

## PM 與開發順序

1. 定義玩家要辨識的單位／塔用途、攻擊前兆、命中結果，列出該軍團至少一項獨有視覺語彙。不可只換顏色或把箭頭當成完整攻擊。
2. 在同一張卡、戰場正常視角與診斷用半尺寸視角驗證同一資產。卡片和實戰必須保持外型、方位與色彩身份一致；兩者的繪圖管線可以不同，但不得回退成抽象幾何圖。
3. 在合法部署位置放入所有新塔，檢查底座／陰影與地面接觸、前後景遮擋、與道路及背景的明度分離。若地圖「可建」資料和畫面看起來不合，另立地圖校準問題，不以美術驗收通過掩蓋。
4. 再檢查待機、移動、攻擊、受擊／死亡或建築運作態；人物圖集至少 4×4，腳底註冊點固定。攻擊特效要有發射、行進、命中三段可辨線索，密集戰鬥時仍能看清敵我。
5. 最後以同一張地圖、相同敵數、同一倍速作軍團對照和前景長局複驗，才批准上線。

## UI／UX 人工簽核

- 128×128 建造卡：看得出塔種，主體不被裁切，透明背景無白／黑框；名稱、費用、用途與圖像對得上。
- 正常戰場：塔不浮空、不像貼紙、不在錯誤地形上；腳點與選取圈一致；射程、等級和戰鬥文字不壓住關鍵細節。
- 半尺寸診斷圖：同一畫面以 50% **渲染比例**檢查剪影辨識。這是工具專用測試，並非宣稱玩家鏡頭可縮至 0.5；如已無法辨識，優先改剪影／對比，勿只放大粒子。
- 手機橫向、桌面視窗各看一次；新手不用點進說明才能分辨可用塔。截圖由人比較並記錄簽核者與日期，工具的 alpha 占比只排除全空白卡，不能代替美術判斷。

## 架構與資料流

`FactionSystem` 決定本族塔列表 → `ArtSystem.preview` 繪製建造卡 → `Building`／`ArtSystem.drawBuilding` 繪製戰場 → `BattlefieldCamera` 轉換視角 → `PerformanceMonitor` 分開記錄主循環、更新、UI、模擬和繪圖呼叫。`scripts/qa-battlefield-acceptance.cjs` 僅從本機測試頁讀取這些既有模組，另開記憶體版 `ProfileStore`，輸出忽略追蹤的 `artifacts/` 截圖與 JSON；沒有資料庫 migration 或 HTTP API 變更。

## 可重跑的本機驗收

1. Node ≥18、Edge、Playwright；於 PowerShell 執行 `npm run serve:test`，測試頁僅在本機 `127.0.0.1:4173`。若該埠已占用，可在伺服器與 QA 終端同設 `TD_TEST_PORT=4175`（須是有效埠）。
2. 另開終端執行 `node scripts/qa-battlefield-acceptance.cjs --faction naga`。若 Playwright 是工作區外的共用套件，先設定該套件的 `NODE_PATH`；不需向正式網站登入，也不讀本機玩家存檔。
3. 可換 `dragonkin`、`dwarf`、`goblin`、`frostland`、`hunter`、`arcanist`、`rogue`、`wild`。每次輸出至 `artifacts/battlefield-acceptance/`；需保存多次結果時用 `--out artifacts/本次名稱`。
4. 對照 `build-drawer.png`、`card-*.png`、`map-geometry.png`、`battle-100.png`、`battle-50.png` 與 `report.json`。工具確認卡片非空白、塔源圖可見像素至少 95% 落入卡片裁切範圍、各塔有合法位置、比例正確、至少 30 個效能影格且無頁面例外；**不會**自動批准畫質。`map-geometry.png` 以黃色顯示邏輯道路、青綠色顯示可建多邊形，必須與原畫人工對照。
5. 短測 fixture：潮門外流、×2、11 與 120 隻高血量怪、一名英雄、一名士兵、英雄 W；娜迦與矮人分別開新隔離頁，暖機 1 秒、取樣 3 秒。長測可執行 `node scripts/qa-desktop-soak.cjs --faction naga --seconds 600 --headed --out artifacts/naga-soak-600`，另以 `dwarf` 對照；每 5 秒紀錄整段影格與長任務，使用隔離的 1 MiB 合成存檔、固定 120 怪、三座塔。先看 `frameP95`、`updateP95`、`drawP95`、`backlogP95` 及略過時間增量。各欄 P95 不相加；`drawP95` 只是 CPU 繪圖呼叫，不包含 GPU 呈現。固定怪不代表自然 50 波，也不能證明玩家當時遠端版本相同。

## 效能放行與風險

在同一設備、瀏覽器、地圖、敵數、倍速下取至少三輪；先比本族 11→120 怪及與矮人對照的中位結果。若 P95 影格超過 33.3 ms、回補／略過時間持續大於 0，或本族同條件更新／繪圖 P95 持續高於對照 25%，標記需調查而非自動歸咎新增軍團。必須用使用者電腦前景 10 分鐘及技能密集時段再驗證；無頭瀏覽器 FPS 不作硬體承諾。若只是卡片或短測通過，不得宣稱「所有特效／卡頓已修好」。

2026-10-05 初次跑娜迦／矮人：兩者 11、120 怪各 120 幀；娜迦更新 P95 約 1.6–1.8 ms、繪圖呼叫 P95 約 1.2–1.5 ms，無回補與略過，未見本族特有短測退化。此結果不推翻玩家前景有卡頓的報告；既有已確認的 UI 存檔複製根因及其修正見 `PERFORMANCE_PROFILE_8D_V08580.md`。地圖合法塔位與實際畫面貼合感仍須人工檢查。

同日另跑龍族與地精：四座龍塔、七座地精塔的卡片均非空白、各自找到合法塔位，短測無頁面例外；龍族 11／120 怪更新 P95 均約 1.6 ms，地精的詳細數據見各次本機 `report.json`。**人工美術尚未簽核**：潮門外流的部分合法平台在背景圖上看來貼近橋、水緣或城牆，塔與場景的接地層次仍突兀。這是地圖視覺／部署標定的待修項，不能以 `legal:true` 或效能通過宣告已解決。

2026-10-06 校正潮門外流：沿未修改的 1536×1024 原畫重新標定石路、城門與五塊草地部署區；舊道路穿入海面、舊合法塔位落在橋／水緣的錯位已消除。娜迦四塔、龍族四塔、地精七塔的實際抽屜、單卡、戰場及疊線圖已截圖；塔卡非空且源圖裁切覆蓋率 ≥99.9%，各塔皆有合法部署點，未見頁面例外。這證明所測塔卡與戰場資產可用，**不等於所有美術已通過人工審美簽核**。畫面證據保存在本機 `artifacts/naga-map-repair/`、`artifacts/dragonkin-map-repair/`、`artifacts/goblin-map-repair/`。

PM 風險：路線和可建區是實際玩法資料，校正後塔可覆蓋的道路區段及怪物抵達時間也可能不同；雖未更動生命／傷害／波次數值，發布前仍須以娜迦、龍族、地精及普通玩家配置複驗前、中、後期的可通關性。背景圖本身未重繪，「背景材質有點假」的主觀觀感仍需玩家看新接地畫面後驗收。

同機 Edge 可見視窗長測：娜迦及矮人各 60 秒，×2、120 固定怪、三座塔，12 個 5 秒桶均回報頁面可見且取得焦點。影格 P95 約 10.1 ms，更新 P95 約 1.6–1.9 ms，繪圖呼叫 P95 約 1.7–2.3 ms；未觀察到持續累積回補或單調增長的堆積記憶體。娜迦啟動初期有一次約 80 ms 的累計略過，後續沒有成長；矮人沒有略過。報告在 `artifacts/naga-soak-60-full/report.json` 與 `artifacts/dwarf-soak-60-full/report.json`。這不是 10 分鐘、自然波次或玩家實際 GitHub 頁面的測試，故**持續卡頓尚未定位或宣告修復**。

發布前 GitHub `main` 曾為 0.85.82，且 `src/td/maps.js` 仍含舊潮門外流幾何；校正後已併入 v0.85.83，提交 `79d0a1e` 的 Pages 部署與線上檔案比對成功。另做埃及軍團 60 秒前景固定 120 怪長測：12 個 5 秒桶均保持可見／聚焦，影格 P95 約 10.1 ms，更新 P95 約 1.5–1.9 ms，繪圖呼叫 P95 約 2.6–2.8 ms，追趕積壓與略過皆為零；報告見 `artifacts/egypt-soak-60-v08583/report.json`。這不等於已量測玩家裝置的快取或自然波次長局。

## 例外、安全、回復

- 工具只連本機 `127.0.0.1` 的指定測試埠；採記憶體管理員測試資料，不讀寫正式玩家檔。輸出只准在專案 `artifacts/` 內，測試截圖不自動上傳。
- 資產載入逾時、缺卡、空白預覽、找不到合法塔位、瀏覽器例外、影格不足會失敗。失敗時保留報告／截圖；先修因，不放寬門檻掩飾。
- 本輪另外修改 `src/td/maps.js` 的潮門外流幾何；不改玩家存檔 schema、資料庫或 HTTP API。回復時將該地圖幾何與其測試一起還原到上一版，玩家存檔無須還原；正式發佈仍需沿用部署備份、正式版號與快取驗證流程。
