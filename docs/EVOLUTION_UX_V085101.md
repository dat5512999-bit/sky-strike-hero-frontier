# 進化展示、外觀切換與載入改善 v0.85.101

2026-10-13。本機完成；本版尚未提交或上傳 GitHub。線上仍以 v0.85.100 發布紀錄為準。

## 產品規劃與範圍

依使用者同意的改善方向，優先處理看不出進化、商城造型遮住進化、開場誤等非必要圖片，以及缺少正常傷害試煉比較。順序為資料與渲染邊界 → 手機展示 → 回歸測試 → 文件版本。此次不重畫美術、不增加英雄、不改英雄強度、試煉數值、商店價格、波次或難度規則。

沿用英雄與軍團內容 Skill 的裝備／存檔／外觀分離原則。沒有新資料庫、網路 API 或額外安裝需求。

## 玩家操作

1. 達到原本波次條件後購買進化石，清場後挑戰火焰惡魔；失敗保留石頭，勝利才消耗並進化。
2. 勝利後顯示原生外觀的放大前後比較、等級／攻擊／生命差異，以及該階被動能力摘要。等級仍歸零，裝備保留。
3. 閱讀結果時戰場停止推進，下一波不能手動啟動；按「繼續戰鬥」恢復。這不覆寫原有暫停或選單狀態。
4. 已裝備商城造型時，畫面會解釋它仍在顯示，可直接切換為進化外觀。離開比較畫面後，可在「遊戲選單 → 設定」切換；「英雄資訊」也有同一控制項。
5. 外觀選擇依玩家、英雄保存，重新開啟仍保留；未進化時仍使用商城／初始外觀。切换不扣款、不移除購買紀錄、不改能力。

比較圖固定顯示原生初始／覺醒／超凡，不是商城造型的進化版。圖片載入中或失敗時會說明暫用原貌，仍可繼續戰鬥。無已裝備商城造型時不顯示無作用的切換按鈕。

## 架構與 API

- `HeroAppearanceSystem.js`：`bind(game,storage)` 讀取並驗證偏好；`mode(game)` 回傳 skin／evolution；`set(game,mode)` 先存成功才更新畫面，儲存失敗返回 false 並提示；`attach/update` 連接兩個入口。
- 儲存沿用 `ProfileStore.adapter('presentation')`，key 為 `hero-appearance`。在目前玩家的 data 內形成 `presentation:hero-appearance` JSON 字串，例如 `{"hunter":"evolution"}`。缺值／壞值回到商城優先；不變更存檔 schema。玩家、測試輪次與商城交易仍分離。
- `HeroEvolutionSpriteArt` 與 `BullWargodArt` 僅在 rank > 0 且選擇 evolution 時，允許進化圖先於已裝備造型繪製。沒有可用進化圖時走既有替代畫法。
- `HeroEvolutionReview.js`：用另一個 Hero 與不含商城覆蓋的 art view 繪製靜態比較；不修改戰鬥實體與造型所有權。圖片變動才重畫；預覽繪圖例外不會阻止關閉結果。
- `HeroEvolutionFlow` 管理成功、試煉、重試訊息；成功比較移到 body 層，避免直式 HUD 遮住按鈕。既有試煉通知仍在戰場層。
- `TDGame.update/startWave` 在成功結果存在時暫停推進／拒絕開波；reset 清除結果。其餘暫停機制未改。

資料關係：ProfileStore → 外觀偏好 → ArtSystem 渲染；HeroEvolutionSystem → lastResult／form → 比較 UI。商城 ownedSkins／equippedSkins 与英雄 equipment／gear 不被外觀偏好寫入。

## 安裝、管理與重現

玩家沿用現有安裝與設定，沒有新相依套件。開發者使用既有 Node 環境，在專案執行：

```text
npm test
npm run check:site
npm run serve:test
```

另一終端執行 `npm run qa:evolution-review`、`npm run qa:evolution-balance`。QA 需要既有 Playwright 套件及 Edge；若目前 shell 找不到 Playwright，將 NODE_PATH 指向已配置的相依套件目錄，不要求玩家安裝。全英雄視覺回歸用 `npm run qa:evolution-all`；可用 EVOLUTION_QA_URL 指定 http://127.0.0.1:4173/td.html。

`npm run qa:local-update` 自行啟動暫時 localhost server，須有 v0.85.100 Git 標籤；可用 UPDATE_BASELINE_TAG 指定已驗證舊版本。它不修改 Git 或工作檔。

管理者使用隔離玩家／測試輪次重現，勿在真實存檔補測資源或強制擊殺。輸出位於 artifacts/evolution-review、evolution-all、evolution-balance、pages-update，均不納入正式遊戲包。

## FAQ

- 已進化但戰場還是商城造型？預設保留原本已購造型；在成功畫面或遊戲選單 → 設定改成進化外觀。
- 切回商城要重買嗎？不用；切換不動交易紀錄与貨幣。
- 看不到切換鈕？只在目前英雄已進化且已裝備商城造型時顯示；不是授予未買外觀。
- 圖片失敗會卡住嗎？有載入／替代提示，結果仍可關閉；網路恢復後可沿用重新載入圖片或重新開啟。
- 更新是否清空存檔？不會主動清除；仍應先匯出備份。瀏覽器主動清除資料／系統儲存回收不在此保證內。
- 測試全勝代表已平衡？不代表，只是固定高等級裝備與腳本策略的比較基準。
