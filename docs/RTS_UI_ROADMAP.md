# RTS／Dark Fantasy 介面改版 Roadmap

## 掃描結論

塔防入口為 `td.html`，視覺集中於 `td.css`；`src/td/main.js` 只收集 DOM，`TDGame` 協調波次、英雄、經濟與 UI。Canvas 戰場與 `ArtSystem`、`WaveSystem`、`BuildSystem`、`EconomySystem`、`HeroRoster` 等領域模組已分離，因此介面可漸進修改，不需重寫戰鬥。

| 目前 UI 架構 | 建議修改 | 涉及檔案 | 主要風險 |
| --- | --- | --- | --- |
| 資源頂欄＋獨立大型波次卡 | 合併為窄型橫向 Wave HUD，加入目標、預告、暫停與速度 | `td.html`、`td.css`、`main.js`、`TDGame.js` | 倒數、暫停與速度顯示不同步 |
| 英雄入口、技能與命令區分散 | 集中為右側英雄指揮面板 | 同上 | 改動既有 DOM ID 會讓事件失效 |
| 戰場與網頁卡片權重接近 | 桌面以大型方形地圖為主，右欄固定資訊密度 | `td.css`、`LayoutSystem.js`（沿用） | 低高度桌面與手機溢出 |
| 按鈕狀態主要靠顏色 | 補齊 Hover、Pressed、Selected、Disabled、Cooldown | `td.css`、`TDGame.js` | 過度裝飾降低 RTS 判讀性 |
| 英雄沒有真正 MP | 藍列明確顯示「冷卻能量」，不虛構資源 | `td.html`、`TDGame.js` | 玩家誤以為是可消耗魔力 |

## Phase 1：指揮介面（v0.21.0，已完成）

- 保留全部遊戲數值、快捷鍵、地圖與角色。
- 完成黑鐵／金色細框 HUD、地圖主視覺、英雄狀態、Q／W／E／R、M／A／H／S、建造／招募與三段速度。
- 沿用 `LayoutSystem`、現有圖集、商店、選取與建造流程。
- 玩家差異：重要戰況集中於一眼可讀的位置，技能與命令不再散落。
- 風險控制：DOM 契約與速度倍率新增自動測試，桌面與手機實測無水平溢出。

## Phase 2：戰鬥回饋（下一階段）

- 加入傷害／暴擊／Gold 跳字、平滑血條、受擊閃爍、命中特效、死亡回饋與選取光圈。
- 優先擴充 `Effects` 類型或建立獨立塔防回饋模組，避免把所有效果塞入 `TDGame`。
- 沿用 `Projectile.owner`、`onKill`、角色 `hit`／`death` 狀態與 Canvas 繪製順序。
- 玩家差異：攻擊是否命中、哪座塔擊殺、資源為何增加會更明確。
- 風險：同屏大量跳字會遮路與掉幀；需物件池／數量上限並避免過亮閃爍。

## Phase 3：資訊工具評估

- 先以可用性測試決定是否加入小地圖、戰鬥紀錄、資源細項與建築快捷欄，不預設全部必須存在。
- 若加入，建立獨立 HUD 子模組，只讀遊戲狀態，不修改經濟或戰鬥規則。
- 玩家差異：長波次與大型科技樹的資訊管理更容易。
- 風險：720×720 單地圖的小地圖可能重複資訊，手機版也可能被額外面板壓縮。

## 驗收原則

每個 Phase 均須通過語法檢查、自動測試、桌面／手機煙霧測試、Console 檢查與文件同步，再開始下一階段。
