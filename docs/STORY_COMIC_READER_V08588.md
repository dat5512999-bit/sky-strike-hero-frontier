# v0.85.88 故事漫畫閱讀器

## 需求與原因

玩家看到第三章凜的頭部被裁掉，也難以從含蓄短句理解故事。舊版用固定橫幅、`object-fit: cover` 和 1.06 倍放大動畫展示直式英雄圖，因此裁去上下內容；文字覆在圖片上，進一步擋住人物。這版改成完整插圖與獨立旁白／對話的雙欄書頁，手機直向則上下排列。

產品範圍是重寫既有四章的閱讀文字、擴充分頁、修正展示和連續閱讀。沿用已存在的角色、情節、插圖與配樂；尚未揭露的南方統治歷史與異常來源不新增定論。每頁有自己的事件和對話，同一場景可在故事延續時再次使用，頁數不代表新增了同等數量的插畫。

## 玩家閱讀方式

從「劇情模式」選章節和關卡，按「觀看本關劇情」或「回顧本關劇情」。每關有 8 頁戰前故事：交代前情、人物、線索、危險、應對與目標。16 關共 128 頁；西境預告另有 8 頁。已通關任務的回顧及管理者預覽增加一頁戰後記錄，完整典藏共 152 頁。

- 按「上一頁／下一頁」或鍵盤左右鍵翻頁；Home／End 跳到第一／最後一頁。
- 「頁碼目錄」可以直接選頁。鍵盤翻到最後一頁會停住，不會誤觸出征。
- 戰前故事讀完後按「開始戰鬥」；「跳過並出征」仍可略過。左上「章節選單」可隨時退出閱讀。
- 回顧結尾可接續已解鎖的下一話。管理者可連續預覽全章；閱讀不完成任務或發放獎勵。
- 插圖保留完整比例，文字區可捲動，底部翻頁按鈕固定可見。手機直向可捲動整頁內容，橫向分欄閱讀。
- 插圖等待時保留備用畫面；失敗可按「重新載入插圖」。開關音樂不重建正在載入的圖片。

## 架構與維護介面

```text
StoryCatalog（既有插圖／關卡／人物／配樂與解鎖）
   ↓
StoryComicBook.stories + aftermath（逐頁白話旁白與對話）
   ↓ pages(mission, includeAftermath)
FrontierApp.storyPages／turnStoryPage／nextStoryReading
   ↓ render(app)
td-story-book.css（完整圖片＋文字格＋對話框＋固定翻頁列）
```

`src/td/app/StoryComicBook.js` 管理閱讀內容和純字串渲染；`pages()` 回傳新頁面物件，保留既有 `storyCards` 的五幕資產契約以相容圖鑑與劇情資料。`FrontierApp` 負責閱讀狀態、頁碼邊界、可接續任務、圖片載入與音樂。`chapterIntro()` 提供章節選單的白話簡介。沒有資料庫、HTTP API、玩家存檔 schema 或新套件。

新增／修訂頁面時，每頁一個事件，旁白說明誰、地點及行動，對話補充角色反應；不要用抽象格言代替事件。`shot` 對應既有本關插圖索引，`speaker` 必須是正式英雄 ID，圖片使用 `contain`，不得重新加入自動放大。戰後事實放入 `aftermath`，只在通關回顧或管理者預覽顯示。

## QA、效能及資料保護

定向驗收涵蓋 136 頁戰前內容、資產和發言角色、前後翻頁／頁碼邊界／快捷鍵、戰後頁與下一話資格、退出不開戰、讀取不解鎖、文字轉義、離線引用、慢載與失敗重試。原先的序章／通關／配樂測試同步更新為漫畫閱讀入口，原世界觀文件雜湊保持不變。

瀏覽器隔離驗收已查看第三章第 2 頁的凜：1280×720、390×844、844×390 均保留頭部、武器與全身，文字不壓在主圖上。頁碼跳轉到第 9 頁、下一話切到「齒輪的回聲」成功，Console error 為零。這是瀏覽器尺寸模擬，不等同所有實體手機的驗收。

所有顯示文字 HTML 轉義；頁碼只接受整數並限制範圍。翻頁是本機閱讀狀態，無資料外送或新增權限。一次只顯示一張主圖和一張對話角色圖，當前圖片載入後才預載下一張。未播放自動翻頁、縮放動畫或整本圖片預載。

2026-10-07 本機驗收：`npm test` 全部 1,043 項通過、零失敗；`npm run check`、`npm run check:release`、`git diff --check` 均通過。測試包含漫畫頁面、序章／通關流程、慢載重試及配樂回歸。瀏覽器尺寸與操作結果如上。此記錄不代表已部署 GitHub Pages；發布結果另以提交與部署紀錄確認。

## 安裝、部署、備份、回復與 FAQ

安裝沿用 Node.js ≥18；在專案根目錄執行 `npm run serve:test`，開啟 `http://127.0.0.1:4173/td.html`，由劇情模式進入閱讀。無新增設定或金鑰。版號提升至 0.85.88，HTML 引入新的 JS／CSS，Service Worker 同步登錄並換快取鍵。

發布需同版包含閱讀器、FrontierApp、CSS、入口、Worker、測試、文件及既有慢載修復。先匯出玩家 JSON，保留前版 0.85.87 提交。回復時成套回復應用與快取版號，保留玩家 JSON；本版未遷移玩家資料。

「為什麼兩側有深色留白？」因為直式人物圖完整放進插圖格，留白保留全身，不會裁頭。「怎麼沒有戰後頁？」一般玩家要先通關，再從回顧讀取；管理者可以直接預覽。「手機看不到下半段對話？」捲動中間內容區即可，翻頁鍵固定在底部。「仍看到舊橫幅？」確認版本 0.85.88，重新載入頁面；不要清除玩家存檔。
