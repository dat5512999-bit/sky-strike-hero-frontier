## 操作與驗收入口

照常進入自由遠征，點「預告」即可看該波首領圖像和名字。登場訊息使用同一個身分。第 30／50 波沿用既有素材是設計選擇，並非載入錯誤。

本機開啟 `boss-preview.html`，可比较原本／新造型，切換待機、行走、攻擊、施放、倒下、暫停逐格和左右方向。預覽使用正式渲染器和 108px／116px 目標高度；窄螢幕會等比縮小。它不寫入存檔或排行榜，背景為現有地圖裁景，並非完整戰局截圖。

## 架構與 API

```text
WaveSystem 出兵 → BossVisualCatalog.apply → monster.bossVisualId / name
WaveHUD 波次預告 → BossVisualCatalog.get → 名稱、圖像與登場訊息
ArtSystem.drawMonster → BossVisualCatalog → BossSpriteBounds → 首領 PNG
```

- `BossVisualCatalog.get(type,wave)`：僅對精確固定波次和既有怪物類型返回外觀描述。
- `BossVisualCatalog.apply(monster)`：只寫入外觀 ID 與顯示名字；進化試煉／練習目標排除。只在正式波次出兵流程呼叫，不在所有 Monster 建構時套用。
- `ArtSystem.bossImage(entry)`：按需載入並共用快取，沿用既有失敗素材重試清單。
- `BossSpriteBounds[id]`：來源圖尺寸、可視高度與十六格 `[x,y,w,h,anchorX,footY]`。避免固定均分切到武器；腳底固定在單位世界位置。
- 新圖集使用四列：待機、行走、攻擊／施放、死亡。受擊使用待機列，不誤播出手。
- 沒有新增伺服器 API、資料庫、帳戶權限或存檔 schema。

## 素材與生成紀錄

使用內建 image_gen，以 `assets/td/enemy-boss-actions-v1.png` 作為風格／格線參考；非重新設計遊戲整體風格。原檔不覆蓋。素材及提示在 `assets/td/bosses/`，提示集為 `prompts.json`。前線戰將與霜潮首領使用 v2，v1 為不載入的初稿；其餘使用 v1。

每套最終圖有 16 個主要角色區塊，實際 PNG 為 1254×1254 且具 alpha。來源不是完全均勻切格，因此以逐格邊界資料繪製。`scripts/inspect-boss-atlases.cjs` 只讀取 PNG 的 alpha 元件，输出候選邊界；換圖後須再看逐格預覽，不應直接信任生成格線或自動偵測。

## 安裝、更新與部署

既有安裝方式不變，不需要新環境變數。遊戲本身不需要 Node 套件。開啟 `td.html` 可本機遊玩；HTTP 預覽執行 `npm run serve:test` 後開啟 `http://127.0.0.1:4173/boss-preview.html`。

部署必須包含完整 `assets/td/bosses/` 最終素材、兩個新增系統腳本、WaveSystem、WaveHUD、td.html、sw.js 和版本檔；不可只替換圖片。確認介面與 Service Worker 顯示 0.85.57。大圖沿用按需下載策略，首次離線且未下載過的新首領圖不保證可用；載入中／失敗會暫用舊首領，確保戰鬥繼續。可在連網時開啟比較頁載入全部首領。未進行遠端部署。

自動測試：`npm run test:boss-visuals`、`npm run check:boss-visuals`。瀏覽器 QA 額外需要 Playwright 與 Edge；啟動 4173 伺服器後設定 PowerShell `$env:BOSS_QA_URL='http://127.0.0.1:4173'`，執行 `npm run qa:boss-visuals`。此專案本次使用桌面環境提供的 Node 套件目錄設定 NODE_PATH，未把本機絕對依賴路徑寫入遊戲。

## FAQ

**首領變成盾牌或雙斧，能力也變了嗎？** 沒有；本次只改外觀與出手圖格，傷害結算及紅色範圍預警仍沿用原規則。

**怎麼還看到舊首領？** 第 30 波刻意保留舊造型；其他波請先確認版本、連網素材是否完成下載。圖片失敗會保留舊圖作為安全替代，不要清除玩家存檔。

**進化試煉也會換成同波首領嗎？** 不會；進化試煉／練習目標不套用固定遠征外觀。
