# 手機建造與配裝辨識優化 · v0.85.62

## 目的與範圍

本次只降低手機戰場的遮擋與誤點成本，不調整塔、士兵、軍團、怪物、經濟、波次、地圖格位或存檔資料。

- 進入建造／部署預覽時，預覽點 96 世界單位內的既有塔與士兵以 30% 不透明度繪製；範圍圈與預覽本體保持完整可見。
- 手指點到重疊的塔或士兵時，優先選擇離觸點最近者；滑鼠仍採原本最上層目標的選取邏輯。
- 選到士兵後，「裝備」快捷鍵會顯示目前裝備名稱，沒有裝備則明示「未裝備」；按鈕仍開啟既有配裝選擇器。
- 手機的「選位置 → 確認部署」兩步驟保持不變，避免手指誤觸就消耗資源。

## 操作手冊

手機玩家選擇建造卡後，在戰場點選或拖曳預覽位置。周邊既有單位會變淡，綠色範圍與新單位預覽會留在前景；選好後按「確認部署」。若多個單位很近，點想選的角色中心附近即可優先選到最近的那名。選到士兵時，戰場旁的裝備按鈕第二行即為現有裝備；點它可更換或卸下。

## 管理、架構與 API

改動集中在三個低耦合位置：`BuildSystem.draw()` 僅改 Canvas 呈現，`BuildSystem.selectAt()` 接收可選的 `preferNearest`，`TDGame.attachInput()` 只在觸控事件傳入該偏好。`ArmoryUI` 僅更新既有按鈕的文字、標題與無障礙標籤。沒有 HTTP API、資料庫、權限、存檔 schema、獎勵池或戰鬥數值改動。

流程為：

`手機點擊 → TDGame 以 preferNearest 選取 → BuildSystem 選最近候選`  
`建造預覽 → BuildSystem 淡化附近既有物件 → 預覽／確認面板`  
`選取士兵 → ArmoryUI 讀取 ArmorySystem.equipped() → 快捷按鈕顯示裝備`

## 安裝、部署、備份與回復

需要 Node.js 18 以上，沒有新套件、資料庫遷移或環境變數。版本為 `0.85.62`，Service Worker 快取鍵為 `sky-strike-v0.85.62`。部署時同步發布 `td.html`、`td-combat.css`、`BuildSystem.js`、`TDGame.js`、`ArmoryUI.js`、`sw.js`、版本標記、測試與本文件。

更新不讀寫玩家進度與裝備；不必清除網站資料。若需回復，先依備份還原手冊匯出既有資料，再回復本次程式與快取版本；舊版仍可讀取同一份存檔。

## QA 清單

1. 手機橫向選建造卡，點既有單位旁邊：附近物件淡化、預覽與射程圈仍清楚。
2. 觸控點兩個重疊命中範圍：選到離觸點最近者；滑鼠仍選最上層者。
3. 手機預覽後不按確認：資源、物件數量均不變；按確認才部署。
4. 選取無裝備／有裝備的士兵：快捷列分別顯示「未裝備」／名稱，點擊仍可開啟配裝器。
5. 執行 `npm run check`、`npm test`。

## FAQ

**淡化會不會讓塔停止攻擊？** 不會；這是繪圖透明度，沒有改變遊戲物件或戰鬥更新。  
**為什麼仍需按確認？** 這是防誤點與防資源誤扣的既有手機保護，這版刻意保留。  
**這會改變電腦版嗎？** 電腦滑鼠的選取排序不變；建造預覽的淡化為共用視覺提示。
