# v0.85.96 劇情漫畫重排與驗收

2026-10-11。本次規劃的第一部主線 44 頁彩色漫畫已接入本機遊戲，新增第 19–44 頁並修訂連續性。劇情模式改為九個按年代排列的段落；原 16 關另放「既有挑戰」，不刪除任務、獎勵或通關紀錄。GitHub 尚未發布，iPhone Safari 真機與作者最終人物辨認驗收仍待完成。

## 玩家如何閱讀

進入大廳的「劇情模式」，預設為「新版故事」。先選左側段落，再按右側固定的「觀看劇情」。章節清單與詳情可以各自捲動，但觀看及開始按鈕不需捲整頁尋找。手機維持橫向，實際閱讀器完整顯示整張漫畫；文字太小時可用「放大拖看」或「故事文字」。

每次只讀所選段落，讀畢返回章節，不連播整本。「護證撤離」分戰前與戰後；戰前讀完先回任務摘要，由玩家按鈕確認才開戰。通關成功儲存後，結算的「閱讀戰後劇情」開啟第 34 頁。敗北或存檔失敗不開放戰後及後續同期段落。

「戰術重現」沿用既有首關的地圖、單位、五波與獎勵，以遊戲防守目標呈現護證撤離；不把原戰場地理或單位造型當成案發當夜的逐一重演。其他 15 個舊關卡沒有套用不相干的新漫畫。這 44 頁是本次第一部主線，不代表後續世界故事全部完結，也沒有提前揭露真凶。

## 故事與美術修訂

古代十頁呈現各族分居、商路往來及協商共同生活；第十一頁在同一河灣展現擴建與世代更替；第十二頁起才是當代。當代雷恩、希爾芙、維菈沿用遊戲英雄辨識特徵，不把古代平民當作三位英雄的年輕版。王子、國王、救援證人及重複出現的配角另有固定外貌。

新增主線依序呈現公共會所閱覽室的王子案、疑似暮影術式、救援與封存紀錄的形成時間矛盾、依法調查遭阻、撤權後護證而遭追捕、銀葉出兵，以及維菈為保護族人痛苦地使用禁術。懷疑不等於定罪；術式有拘束並消耗亡魂的代價，不當作光榮勝利。

最後修訂統一第 23 與 27 頁的屏風布面焦紋，保留救援紀錄的乾淨屏風；另修正現代證件及制服、配角誤似王子、被拒調閱的紀錄卻已拿到、以及未設定的存活人數等問題。完整對白另有可選的文字閱讀，並沿用現有劇情音樂的情緒切換，沒有新增錄音配樂的宣稱。

## 架構與保存

`StoryMangaCatalog` 保存 44 頁圖像、年代、對白和音樂情緒；`StoryMangaFlow` 保存段落、戰前戰後與通關條件；`StoryManga` 負責閱讀、重試及本段下一頁預載。`FrontierApp` 顯示新版故事及既有挑戰，結算與解鎖提示共用 Flow 顯示名稱。

正式圖片為 [manga-v2 資料夾](../assets/td/story/manga-v2/) 下的 `page-01.webp` 至 `page-44.webp`，每張 1536×1024，44 張合計 27,815,212 bytes，約 26.53 MiB。閱讀時只請求目前頁及本段下一頁；不在開始遊戲時一次解碼全部漫畫。圖片沿用按需快取，未讀的頁面不保證離線可用。

新版書籤為目前玩家 `manga:bookmark-v2`，各段落獨立保存並記錄最近所選段。`manga:bookmark-v1` 原值不動，因頁序不同不自動猜測對應。管理者巡讀不寫通關或書籤；沒有新增資料庫、伺服器 API 或存檔遷移。

## 重建與回復

一般玩家只需依 [安裝手冊](INSTALLATION.md) 啟動遊戲。維護圖稿需 Node.js 與 `sharp`，瀏覽器 QA 另需 `playwright` 及 Microsoft Edge；可用既有 Codex 工作區依賴，不必把本機依賴絕對路徑提交到遊戲。

1. 修改圖稿時建立新的版本檔名，保留舊 PNG；更新製作清單和 Catalog 的 `sourcePath`。
2. 執行 `npm run prepare:manga` 及 `npm run prepare:story-review`，兩者保持全圖比例、不裁切。正式轉檔不依來源時間戳跳過，選回舊 PNG 也會確實重建。
3. 修改文字或頁序時同步正式 Catalog、review-catalog 和 Flow，執行下列驗收。
4. 完整版本回復需還原整包程式與素材；不要只替換閱讀器或清除玩家網站資料。發布後回復使用新的 Worker 快取版本，詳見 [備份還原](BACKUP_RESTORE.md)。

## 驗收結果

2026-10-11，`npm test` 全套 1,122 項通過；`npm run check` 及三個漫畫模組語法檢查通過。`npm run check:site` 列入 792 個正式檔案，44 張正式 WebP 皆在其中，concepts 和 QA 產物不發布。正式與審閱 WebP 的內容雜湊一致，來源 PNG 尺寸、頁序、唯一性、情緒代碼、修訂來源都有自動測試。

- `npm run qa:story-layout`：Edge 1920×900、1365×768、844×390、667×375，九個封面與 16 關操作逐一驗證；外層不捲動，主要按鈕至少 44px、可點擊。
- `npm run qa:manga`：Edge 1365×900、844×390、667×375，44 頁逐張解碼；八個閱讀段、戰前／戰後、管理者零寫入、未解鎖防越界、書籤、拖曳、文字及斷圖重試通過。
- `npm run qa:story-review`：相同三尺寸，審閱頁全 44 頁、續讀、縮放、文字、儲存拒絕與全螢幕拒絕處理通過。
- 結算到第 34 頁使用成功結算測試資料走實際儲存／結算按鈕接線；不是重新跑完整戰鬥或平衡測試。既有任務玩法欄位另與快照比對，保持不變。

瀏覽器測試使用獨立設定檔，不操作作者的玩家資料。報告與截圖在 `artifacts/story-layout/`、`artifacts/story-manga/`、`artifacts/story-v2-review/`。手機結果是橫向模擬，不代替 iPhone Safari 或加入主畫面模式的實機驗收。

執行上述瀏覽器 QA 前，在專案目錄的第一個 PowerShell 視窗設定 `$env:TD_TEST_PORT='4189'` 後執行 `npm run serve:test`，保持伺服器運作；另一個視窗執行 QA 指令。若使用不同網址，可分別設定 `STORY_LAYOUT_QA_URL`、`MANGA_QA_URL`、`STORY_V2_REVIEW_QA_URL`。找不到 sharp 或 playwright 時，先依工作區依賴設定 `NODE_PATH`，或在開發環境執行 `npm install --no-save --package-lock=false sharp playwright`；這些工具不屬於遊戲執行期下載內容。
