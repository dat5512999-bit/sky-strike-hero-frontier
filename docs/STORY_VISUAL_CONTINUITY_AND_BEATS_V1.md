# 劇情人物連貫與五幕節奏

## 目的

同一人物在任何章節都必須能以遊戲內既有英雄立繪辨識；劇情卡不得以「看起來像同一個陣營」的陌生臉替代正式角色。每關由三張擴為五幕，讓玩家在開戰前理解正在發生什麼、誰的立場受影響、此戰要完成什麼，以及成功後改變了什麼。

## 目前規則

`src/td/app/StoryCatalog.js` 的每張卡都有：

- `cast`：正式登場的英雄 ID，必須存在於 `HeroRoster.CLASSES` 並具備 `selectionArt`。
- `visualPolicy: 'cast-bound'`：前端會在畫面右上顯示該角色的正式英雄錨點，所有章節重複使用同一來源。
- 五個固定節點：抵達／人物與立場／本關目標／立即抉擇／守住之後。

第二章石環與赤土原先兩張使用無法對應世界觀人物的通用人像，已改為場景底圖並以雷恩、戈爾的正式英雄錨點敘事。第三章的凜、奇克與第四章的賽洛也會顯示既有英雄錨點；不再只以空場景要求玩家自行猜測說話者。

## 序章的處理界線

序章 `PrologueData.js` 內的銀葉王、王子、公主、禁衛軍團長、國王與首相仍是 `pending-approval`，尚無核准外觀。它們不能被當作正式角色參考來製作或驗收新圖；在有核准設定圖之前，必須維持為概念分鏡，不能宣稱其畫面是正式定稿。

## 驗收

執行：

```powershell
node --test tests/td-prologue-cinematic.test.js tests/td-story-maps.test.js
```

測試會確認所有可玩任務與第二章預覽均為五幕、每張卡都有可解析的角色錨點，並拒絕石環／赤土已退役的通用人像資產。視覺驗收時，逐章確認右上角色名稱、臉部與選角圖一致；若要加入新人物，先建立並核准其正式參考圖，再允許加入 `cast`。
