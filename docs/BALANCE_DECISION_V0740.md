# v0.74.0 第三階段平衡判定

## 產品決策

第三階段不直接改塔價、升級費、擊殺金或波次結算金。原因是實戰資料保存在玩家瀏覽器，原始碼內沒有足以支持改價的樣本；單人單局也容易受操作失誤與掉落影響。

## 判定門檻

固定同一張地圖、難度、英雄與軍團，擴軍、核心升級、混合三種策略各完成至少三局，共九局。自由遊玩仍保留紀錄，但不計入受控樣本。

戰況頁顯示各策略局數、勝率、平均到達波數與總進度。未達門檻時只回報缺少樣本；達標後才檢查策略間進度差距和通關局剩餘金幣比例。

## 安全邊界

- 判定是決策輔助，不會自動修改任何遊戲數值。
- 若策略平均進度相差至少三波，先檢查投資效率，不直接提高基礎塔價。
- 若至少三局通關，且六成通關局的剩餘金幣達總投入 25%，才提示經濟可能偏寬鬆。
- 不採用「提高塔價」或「大幅提高波次結算金」作為預設方案。

## 驗證與還原

執行 `npm run check` 與 `npm test`。還原時回退 `BattleReportSystem.balanceReadiness`、戰況頁平衡判定區、對應樣式與快取版本；舊戰績格式不需遷移。
