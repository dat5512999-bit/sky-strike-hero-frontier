## 玩家怎麼使用

大廳「設定與存檔」或戰鬥「選單 → 設定」新增「遊戲診斷」，提供：

- 匯出診斷資訊：產生 hero-frontier-diagnostics.json，檔案只包含診斷摘要，與「匯出存檔備份」不同。由玩家自行決定是否分享，不會自動傳送。
- 清除診斷紀錄：只清除專用診斷 key 與本頁舊紀錄，不刪角色、進度、金幣、鑽石、造型或完整備份；之後會開始新的有限紀錄。
- 狀態說明：若瀏覽器拒絕儲存或空間不足，顯示目前僅能暫存在本頁，建議關閉前匯出。診斷失敗不會阻止遊戲。

安全暫停錯誤畫面也新增「匯出診斷資訊」，原有「匯出存檔備份」保留。若上次正在戰鬥，但沒有正常離開標記，重新開啟時會提示可匯出診斷；提示明說「這不一定是當機」。強制關閉、重新開啟另一個遊戲分頁或系統中止都有可能留下相似狀態，不能只憑這個標記判定記憶體不足。

切到其他 App／鎖屏而收到背景事件時，遊戲會暫停並放開搖桿／鏡頭手勢。原頁回到前景後顯示「遊戲已暫停」，按「繼續戰鬥」才恢復。原本手動暫停或開著其他暫停選單時，不會擅自解除暫停。若已換局，不會用舊局標記恢復新局。既有 pageshow.persisted 重新載入策略仍保留，用於跨圖鑑頁回來時讀取最新存檔；本輪沒有增加中途逐幀自動續局。

## 記錄什麼與保留限制

專用 localStorage key：heroFrontierDiagnosticsV1。最多保留三次開啟，每次最多 64 筆事件；序列化輸出最多 32768 個字元，超限優先淘汰較舊次數及事件。字元上限不是實際磁碟或 RAM 精準量測，UTF-16 最壞約 64 KiB 的字串內容。持久化和匯出都走同一白名單與裁切流程。

| 類別 | 保存欄位 |
| --- | --- |
| 版本及環境 | 程式版本、平台／瀏覽器類型提示、iOS 版本提示、是否 standalone、初始 viewport 與 DPR |
| 戰場 | 畫面、英雄／軍團／地圖 ID、波次及準備／進軍 phase、暫停／背景／運行狀態、倍速 |
| 負載 | 軍隊／怪物／彈體／特效數，圖片 ready／active／queued／failed 與 RGBA 規模估算 |
| 最近操作 | 白名單按鈕／技能嘗試、選英雄／軍團／地圖、部署／購買嘗試、開波、背景／前景、旋轉 |
| 錯誤 | 已知錯誤類別，最多四個 JS 檔名及行／欄；安全暫停、未處理例外／Promise 拒絕、Canvas 事件及圖片最終失敗 |
| 開啟狀態 | session 的隨機短標記、epoch 毫秒時間、正常離開標記、最後摘要及最近戰場摘要 |

不保存完整玩家存檔、帳戶名字、貨幣清單、裝備清單、輸入文字、原始 User-Agent、裝置識別碼、完整網址／路徑／查詢參數、原始錯誤訊息或原始堆疊。環境只是瀏覽器可取得的提示，無法精確推算 iPhone 型號，回報時仍需玩家另提供型號。操作是「嘗試」而非成功交易證據，不拿診斷檔計算獎勵或還原貨幣。

最近戰場摘要在回大廳後仍保留於 lastBattle，避免回報時只看到大廳。心跳五秒最多一次，常規寫入至少相隔一秒；背景、錯誤及離開時盡力立即保存。背景期間不做週期性心跳寫入，不新增 interval。儲存寫入失敗後退避六十秒，仍可從記憶體匯出。

這是盡力保留的診斷，不是交易日誌。OS 突然終止前最後一瞬間、初始化之前的錯誤、外層手機 shell 自身失敗或沒有收到生命週期事件的情境，可能沒有紀錄。不同遊戲分頁共用此診斷 key，並行寫入可能取代彼此的較新內容；調查時以單一遊戲視窗重現，不把它當跨分頁精確稽核。已匯出的檔案須由玩家自行刪除。清除診斷不是停止未來記錄。

## 架構、資料夾與內部 API

新增兩個模組，td.html 在現有遊戲／大廳／音效初始化後載入，Worker 與 iOS 資源包已納入。

```text
TDGame：開波／安全暫停／finally 心跳
                         ↓
GameDiagnostics.js（白名單資料、有限 session／event）
    ├─ 專用 localStorage key（不讀完整 ProfileStore）
    └─ 有界 JSON 匯出

GameSessionLifecycle.js
    ├─ 可見性／pagehide／pageshow／旋轉／Canvas 事件
    ├─ 有限按鈕／技能嘗試與全域 JS 故障
    ├─ 搖桿、鏡頭釋放與手動續玩
    └─ 大廳／戰鬥設定、復原畫面、非正常離開提示
```

| API | 用途 |
| --- | --- |
| game.diagnostics.record(type,details,error) | 記錄白名單事件；識別碼限制字元，錯誤會裁切與去識別 |
| failure(phase,error) | 保存安全暫停原因並嘗試立即寫入 |
| tick() | 五秒心跳；放在 RAF 的 finally，自己的例外不能中斷下一幀 |
| export() | 回傳經相同白名單與大小限制的 JSON 字串 |
| clear() | 清除專用 key 及舊記憶體紀錄，回報是否成功移除儲存 |
| close()／reopen() | 保存正常離開或頁面復返標記 |
| GameDiagnostics.snapshot(game) | 只讀白名單摘要與 assetStore.stats，不遍歷 ready getter、不複製整份玩家資料 |
| GameSessionLifecycle.attach(game) | 單一遊戲只安裝一次事件；dispose 可解除本模組監聽 |
| game.sessionLifecycle.reset() | 清除舊局背景恢復標記，不清除診斷或存檔 |

沒有新增 HTTP API、伺服器、資料庫、分析 SDK、權限要求、安裝套件或自動上傳。原生開發包的隱私／支援說明產生器同步描述診斷內容、限制與匯出／清除方式；這不是發行者已核准正式隱私政策。

## 故障分析與防再發（8D）

此前的主要缺口：錯誤只留於本頁 game.runtimeFault，程序被系統關閉後無法取得；單純把空白／重開標記為當機會誤判。此次將必要摘要獨立有界持久化，以 open、screen、status 判定「可能未正常離開」，並保留不確定性。沒有利用缺少標記來宣稱 OS 記憶體終止已獲確認。

背景事件不再只停止音效與搖桿：同時停止推進，清除時鐘累積，回來時需確認。模擬迴圈另外檢查背景與待恢復標記，避免其他按鍵處理誤改 paused 後自動開始跑。既有手動暫停、選單暫停與換局保持原義。

漏檢防線加入 recorder 的資料／容量／儲存故障測試，以及真正手機入口的匯出、遮蔽、清除與背景流程測試。一般操作與故障均在隔離瀏覽器資料測試，未拿使用者帳號做注入。永久措施的程式驗證完成，但實體 iPhone 鎖屏、程序被 OS 終止及長局仍未結案，也未建立背景監控。
