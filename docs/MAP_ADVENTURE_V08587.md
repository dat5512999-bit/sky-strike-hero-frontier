# v0.85.87 地圖行動

日期：2026-10-07；模組版號 1.0.0。

## 產品範圍

六個方向全部加入正式遊戲：可操作環境機關、修復據點、英雄救援、明碼交易、預告地形轉折、跨關結果。每張正式戰場有 1～2 個互動地標，並非每張都塞滿六種，以免手機操作和戰鬥決策過載。沿用現有英雄、軍團、地圖與故事人物，不新增可玩英雄。

不改玩家發布的怪物路線，也不以圖片像素決定可否走路。環境轉折只開放既有部署區內的一個平台，不封鎖道路、不移走守軍。永久記錄目前影響後續戰鬥資源及偵察；沒有新增故事分支影片、天氣系統或隨機新道路。

## 玩家操作

1. 從劇情或自由遠征選擇戰場和隊伍，開始戰鬥。
2. 點畫面底部「地圖行動」，或直接點地圖上的地標。面板開啟時暫停；關閉回到開啟前的暫停狀態。
3. 面板縮圖的編號對應下方地標；點「查看位置與效果範圍」會移動鏡頭，縮圖顯示作用範圍。先確認敵人位置、成本、期限。
4. 按行動，成功後自動關閉面板。修復與救援派英雄前往，仍可以手動改令；離開保留已累積進度。
5. 結算查看本局結果。劇情勝利才記錄世界結果；自由遠征不改故事進度。

機關全局限兩次，每波最多一次，只在開波後使用。水閘持續 7 秒，地面敵人移速降至 55% 並揭露隱形；寒流 6 秒、60%；脈衝 7 秒、75% 並揭露。飛行敵人不受減速。落石對範圍內地面敵人造成 45＋波次×5 混沌傷害和 2 秒緩速。撲滅煙障將本波與接下來兩波煙障護甲降至零。

修復需 60 金＋1 木；英雄在 72 範圍內累積 4 秒，死亡時不累積。偵察地標完成後持續揭露指定路段的隱形敵人；回聲機座修復後才能啟動脈衝。

救援限定第 2～5 波，英雄在 72 範圍內累積 5 秒；60 範圍有活敵人時暫停，波間整備不累積。完成獎勵 65 金＋2 木，只發一次；第 6 波開始仍未完成就失效，不影響主線勝敗。

交易三選一：75 金換 20 秒路段支援（地面敵人移速 65%）、60 金換 2 木，或拒絕且不扣款。選後不能再次付款。赤土終站的奧魯姆收費保護自己也要經過的道路，呼應他因自身利益離開獸人部落；他不是投效玩家的第二位可控制英雄。使用戰牛出征時不另外畫出第二個奧魯姆。

## 跨關支援

故事勝利且修復、使用機關或救援至少一項成功時，產生一次相鄰關卡支援。交易本身不觸發額外永久獎勵。重玩同一任務不重複派發；下一關勝利時消耗收到的支援。下一關失敗可帶同一筆支援重試，不是額外累積金幣。

支援不進玩家鑽石錢包：偵察情報 35 金並揭露路段；補給 50 金＋1 木；見證情報 35 金＋1 木並揭露；調查器材 25 金＋1 木；觀測支援 40 金＋1 木；水閘維修補給 30 金＋1 木。每筆支援按固定來源派發一次，玩家分頁與故事新周目互相隔離。

## 管理與架構

不新增資料庫、網路服務、依賴或角色解鎖條件。所有互動透過既有戰鬥生命週期和資源系統。

```text
maps.js 已發布道路／部署多邊形
  └─ AdventureCatalog.describe → 關卡地標、範圍、效果資料
      └─ AdventureSystem → 成本、時限、進度、減速、救援、結果
          ├─ AdventureView → Canvas 地標、編號縮圖、暫停對話框
          └─ AdventureIntegration
              ├─ TDGame／WaveSystem／MapPressureSystem：戰鬥更新
              ├─ BuildSystem：平台與地標部署提示
              ├─ ChapterCheckpointSystem：可選 adventure 欄位
              └─ ProfileStore.complete：任務與地圖結果同筆保存
```

資料夾為 `src/td/adventure/` 五支腳本（含 AdventureArt），樣式 `td-adventure.css`，測試 `tests/td-map-adventure.test.js` 與 `tests/td-map-adventure-art.test.js`。載入位於 td.html 原系統之後，無需修改現有關卡引擎。

調整地標名稱、種類、相鄰關卡、效果秒數和支援獎勵，在 AdventureCatalog 修改。位置從已發布部署多邊形中心生成、效果指向已發布道路中段；不讀取美術圖像碰撞。若重畫地圖或移動塔區，需重新做實景定位驗收，避免地標看起來落在不合理位置。

## 介面與存檔

無新增 HTTP API；使用以下本機 JavaScript 介面：

- `AdventureCatalog.describe(map)`：回傳關卡互動定義或 null，不改輸入道路。
- `AdventureSystem.configure(map, context)`：開始一局，從指定故事玩家讀支援。
- `offers(nodeId)`：成本、效果、停用原因；`act(nodeId, action)`：回傳 `{ok,message}`，先驗證後扣款。
- `update(dt)`：暫停時不運算；dt 上限 0.25 秒，範圍掃描每 0.2 秒一次。
- `snapshot()`／`restore(data)`：保存有限狀態、平台與效果；還原不再發獎勵。
- `writeVictory(state)`：只寫入 ProfileStore 正在交易的副本；玩家或周目改變就拒絕，失敗不留半筆進度。

玩家 ProfileStore 原 key 保持 `heroFrontierProfilesV1`。各玩家 `data['adventure:world-v1']` 是 JSON 字串，結構為 `{version:1,deliveries:{mapId:[{id,kind,claimed}]},history:{missionId:result}}`。可選資料損壞時略過，不阻止基本玩家資料使用。

章節 key 維持 `heroFrontierChapterCheckpointV1`、schema 1，新增可選 `adventure`；舊檔不要求此欄位。每次章節 capture 只寫 storage 一次。正式玩家備份和故事新周目均使用原介面。

## 安裝部署與更新

1. 使用既有安裝流程（Node.js 18+），在專案執行 `npm run serve:test`，開啟命令列顯示的本機網址，再開 td.html；不能直接以 file:// 作為正式驗收。

## 備份與回復

先使用個人頁匯出玩家資料並保存到其他位置，再更新版本。此備份已包含地圖支援。需要章節續玩時，依既有備份手冊一起備份章節 key。

版本回復應在備份後以 Git revert 撤銷本版提交、重新發布完整上一版；上一版基準 `6fbe1a8`（v0.85.86）。不要 reset --hard、清空 localStorage 或只發布舊 SW 而保留新 HTML。舊版本忽略可選地圖欄位，但不會操作新地圖支援；恢復新版後可繼續讀取。回復後若再更新，務必核對完整資產與 SW 的同版性。

## FAQ

**為什麼機關不能按？** 尚未開波、本波已用過或兩次額度用完；面板直接顯示原因。

**付了修復費卻沒有立刻完成？** 英雄要靠近地標，保持存活累積 4 秒；進度圈顯示完成比例。

**救援沒完成會輸？** 不會；只失去額外補給，城門守衛仍是主目標。

**為什麼我不能在地標中央放塔？** 地標本體保留操作空間，旁邊仍沿用原部署規則；不限制你修改怪物行走路線。

**每次重玩都能拿前關金幣？** 來源只派發一次，目標關勝利消耗；失敗重試同一筆，不累加到帳號錢包。

**退潮後怪物會換路嗎？** 本版不會。只開放預告的部署平台，維持已設定路徑。

**圖示看起來不像地圖上的水閘？** 正式版已使用透明插畫圖集，不再畫簡易輪子符號；若仍看到舊符號，核對 0.85.87 並使用更新頁刷新完整資產。地圖底圖本身不需重畫。
